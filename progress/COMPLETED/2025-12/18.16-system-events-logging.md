# 18.16 System Events Logging Expansion

**Status**: COMPLETED
**Priority**: Low
**Phase**: 18 - Platform Polish
**Dependencies**: None

## Overview

The `events` table in the general database was designed as a system event log for debugging and analytics, but it's currently underutilized. Only `system/state/changed` events from core-daemon are logged.

Expand event logging to capture more useful system telemetry.

## Current State

- Data-logger only subscribes to `system/state/changed` topic
- Events table infrastructure exists but is barely used
- Missing sensor readings, mesh events, service lifecycle, etc.

## Acceptance Criteria

- [ ] Data-logger subscribes to additional MQTT topics:
  - [ ] `sensor/+/reading` - Sensor data (sampled, not every reading)
  - [ ] `mesh/connection/+` - Mesh network events
  - [ ] `service/+/lifecycle` - Service start/stop events
  - [ ] `camera/capture` - Camera capture events
- [ ] Event retention policy (auto-cleanup after N days)
- [ ] API endpoint to query events with filters (topic, time range)
- [ ] Consider event sampling to avoid database bloat
- [ ] Update database schema docs if needed

## Technical Notes

- Balance between comprehensive logging and storage efficiency
- Consider a configurable sampling rate for high-frequency events
- Events should be queryable via Datasette for debugging
