# 18.17 AI Inference Logging Fix

**Status**: COMPLETED
**Priority**: Medium
**Phase**: 18 - Platform Polish
**Dependencies**: None

## Overview

The `ai_inferences` table exists to log AI inference requests for debugging and analytics, but HTTP API calls bypass MQTT publishing, so no inferences are being logged.

## Problem

The UI communicates with ai-service via HTTP API (`/api/inference`, `/api/chat`, etc.). These endpoints directly return responses without publishing to MQTT.

The data-logger subscribes to `ai/inference/response` MQTT topic to log inferences, but since HTTP calls never publish there, the `ai_inferences` table remains empty.

## Current Flow (Broken)

```
UI → HTTP API → ai-service → response (no MQTT publish)
                                ↓
                         data-logger never sees it
```

## Desired Flow

```
UI → HTTP API → ai-service → response
                    ↓
              publish to MQTT → data-logger logs to ai_inferences
```

## Acceptance Criteria

- [ ] HTTP API inference endpoints publish responses to MQTT for logging
- [ ] Verify `ai_inferences` table populates after chat/inference calls
- [ ] All inference types logged: qa, image_classification, multimodal
- [ ] Processing time and success/failure accurately captured
- [ ] Add tests verifying inference logging works

## Technical Notes

The fix should add MQTT publishing in the HTTP API handlers:

```python
@app.post("/api/inference")
async def inference(req: AIInferenceRequest) -> AIInferenceResponse:
    resp = run_inference(req, pre, response_source=service.response_source)
    # Add this line to enable logging:
    if service.bus:
        await service.bus.publish("ai/inference/response", resp.model_dump_json())
    return resp
```

Similar changes needed for:
- `/api/chat`
- `/api/image/classify`
- `/api/chat/multimodal`
